1

Why I publish this at all

I ask clients to rely on documented integrity. Accept that an image corresponds to a source because a digest was computed at acquisition and matched afterwards. Accept that a record was made when I say it was made, because it was written while the work was happening. That is a reasonable thing to ask.

It is a less reasonable thing to ask from a firm whose own published material can be edited overnight without leaving a mark, which is the ordinary condition of most websites. So I hold this site to the same discipline. The footer at the bottom of every page states which document you are reading, when it was last revised and a digest of the text it was built from, and it links to the history of that file in a public repository. The digest comes from source you can read, produced by a tool you can run yourself; section 3.2 sets out how to reproduce it without any help from me. What the other values do not establish is at section 5, with the limits of the whole mechanism.

1.1

What the mechanism is for

It answers one narrow question. Has the published text changed since it was stamped, and if it has, is the change on the record?

That question matters here more than it would on a brochure. The rate schedule on this site is the schedule attached to the engagement letter, and the refusals are repeated word for word in that letter. The limits of each capability are published here so that nobody meets one for the first time in a deposition. All three are worth less than they look if the version you read in March cannot be told apart from the version quoted back at you in November.

It is also a small claim, deliberately. Section 5 spends longer on what this does not do than the sections above spend on what it does, for the same reason every capability on this site is published next to its limits.

2

The footer fields

The chain-of-custody footer renders at the bottom of every page in this lane, and in a reduced form on the emergency page, which carries no navigation. Up to four values, each meaning something specific. Where a page has not been through the stamping run described at 3.2, the digest row is absent. I would rather leave a gap than print a number nobody computed.

Chain-of-custody footer — field by field
FieldWhat it isWhat this does not establish
PAGE The canonical path of the document you are reading, as published. The same string used in the permalink and in the sitemap. Does not establish that the page was reached over an unmodified connection, or that an intermediary or an archive has not altered what was delivered to your browser.
REVISED The date of the last substantive revision. It is written into the front matter of the source file, rendered in ISO 8601 with an offset from UTC, and it appears again in the specimen header at the top of the page. Does not establish that no edit was made after that date. It is a value I write; the commit history at section 4 is the record that can contradict it.
SHA-256 (SOURCE) A SHA-256 digest over the source body of that page, meaning the whole file below the front matter. It is computed by a build tool held in the public repository and committed alongside the file.Where a page cannot be stamped, the row is omitted rather than filled with something false. Does not establish who wrote the text, when it was written, or that it is true. A digest is a statement about bytes and nothing else.
prior versions A link to the commit history of that exact file in the public repository, which is where prior versions of this site live. Does not establish that the history is complete. Git history can be rewritten by whoever controls the repository. See section 5.2.
3

The hash, and what it is computed over

The digest is taken over the source body of the page: everything in the source file after the closing delimiter of the front matter block, encoded as UTF-8. It is not taken over the rendered HTML that arrives in your browser.

That choice has a drawback, and the drawback is worth stating before the reasons. Because the rendered page is assembled at build time from the source body plus a shared layout, the digest does not cover the navigation, the specimen header, the emergency band or the footer itself. It covers the argument of the document, which is the part specific to that page and the part that would matter in a dispute about what was published.

3.1

Why the source and not the rendered output

Two reasons, and then a piece of plumbing.

A digest over rendered output would move whenever anything shared moved. A new item in the navigation. A typo corrected in the footer. A different build of the site generator. A value that changes for reasons unrelated to the document teaches a reader to ignore it, and an integrity signal that alarms routinely is worse than none at all.

It would also be unverifiable unless you reproduced my build exactly, which is trusting my toolchain instead of checking my text. Hashing the source means anyone with a checkout, a shell and a SHA-256 implementation arrives at the same value.

The third reason is plumbing rather than principle. The front matter is excluded so that the stamp can be written back into the file without invalidating itself. The digest lives in the front matter, the front matter is not part of what is hashed, so the value survives the run that records it.

3.2

Verifying it yourself

None of this needs my cooperation. The repository is public and the tool that writes the stamp is in it.

  1. Clone the repository: git clone https://github.com/wirewalktech/forensics-wirewalk
  2. Check every page at once, using the same command I run before publishing: python3 tools/stamp.py --check. It exits non-zero and names any file whose committed digest does not match its body.
  3. Or check a single page by hand, without running my tool at all. Strip the front matter and hash what is left:
    awk 'f{print} /^---$/{n++; if(n==2) f=1}' versions.html | shasum -a 256Reproduces the digest byte for byte where the source file ends in a newline, as mine do.
  4. Compare the result with the value printed in that page's footer, and with the value of content_sha256 in the file's front matter. All three are the same string or something is wrong.

The second form is the more useful one, because it uses no code of mine. If you would rather read the build tool before you trust it, it is short enough to get through in a sitting and it is at tools/stamp.py.

3.3

What a match proves, and what a mismatch means

A match proves one thing. The source file in the repository at the commit you checked out is byte for byte the source that produced the digest in the footer. It says nothing about whether the sentences are accurate, whether the prices are honoured, or whether the page was published on the date it claims.

A mismatch is not automatically evidence of anything sinister, and I would rather say so than let a reader over-read it. The ordinary cause is dull: a page edited and published without the stamping run having been made, which is a process failure on my side and exactly the class of failure the check exists to surface. What a mismatch does establish is that the text in front of you is not the text that was stamped, and that someone should be asked why.

4

Prior versions are a repository, not an archive I curate

Prior versions of every page are the real commit history of a public repository:

github.com/wirewalktech/forensics-wirewalk

The distinction matters. A curated archive is the set of documents a publisher chose to keep, which means the interesting version is the one that is missing. A commit history is the working record of the site: every change to every file, each with a message and a diff, and with the recomputed digest beside it wherever that commit went through the stamping run. Nobody selects what goes into it, because it is the same record the site is built from. The link in each page's footer goes straight to the history of that one file, so you are not hunting through the repository to follow one document.

At first publication every page has a single commit. There is no dressing that up and I would not want to. A site published today has no history yet, and a page claiming a richer one would be the first thing worth checking. This becomes useful in its second year, which is also the first point at which anyone would want it.

4.1

The version number and the revised date

The version in the specimen header moves on a stated rule, rather than on a judgement about how important a change felt at the time.

Versioning rule
ChangeEffect
A correction that does not alter meaning: spelling, a broken link, markupno version change
A change to wording that alters what a reader would understand the practice to be committing tominor increment
A change to a published price, a rule citation, a refusal, or a term reproduced in the engagement letterminor incrementand a new revised date
A restructure that changes the clause numbering, so that a reference to a section number would no longer land where it didmajor increment

The last row exists for counsel rather than for me. Clause numbers are published so that a reader can say your section 3.2 says, and a number that quietly comes to mean something else is worse than no number at all. So where the numbering changes, the major version changes with it, and the old numbering stays readable in the commit history. What the version number does not do is at section 5. It records which edition you were shown. It holds no price and binds nobody.

4.2

What is not in the repository

The repository holds the source of this website and nothing else. No client material, no matter names, no engagement records, no correspondence, no evidence of any kind. Nothing about an engagement is ever committed to it, and the version history of a published page is not a record of any matter. Evidence handling is governed by its own published terms, and the store described there has no connection to this repository.

5

The limits of this mechanism

Read this section as carefully as section 3. Everything above is an integrity control over published text. It is not a timestamping authority, it is not notarisation, and it establishes nothing whatever about my work product.

Integrity mechanism — reach and limits
ComponentWhat it establishesWhat this does not establish
Source digest in the footer That the published text of this page corresponds to a specific source file, and that a silent edit to that text will not go unnoticed by anyone who checks. No trusted time. No authorship. No notarial act. It is not a qualified electronic timestamp, and I make no representation that it is admissible for any purpose in your matter. Admissibility is the court's decision and nobody can promise it.
Commit history An ordered, public record of changes to each file, including the change that was made and the digest afterwards. Does not establish that the record is immutable. It is hosted by a third party and controlled by me, and the dates in it are supplied by the committer rather than attested by an authority.
Version and revised date Which edition of a published term you were shown, so it can be compared with the edition quoted to you later. Does not create a contract, hold a price, or bind anyone. The rate that applies to an engagement is the one in the signed engagement letter, on the terms at rates.
The mechanism as a whole That I apply to my own published material the kind of control I describe applying to evidence. Establishes nothing about the quality, soundness or admissibility of any examination, report or opinion. A verifiable website is not a verified examiner, and it is no substitute for reading the method and testing it.
5.1

Why I am not claiming more

There is a version of this page that would call the same four values a chain of custody for published content, or tamper-proof, or an application of the standards my method is written against. Each of those is a small overstatement, and small overstatements are the material a cross-examination is built from. What a hash committed next to the file it describes actually gives you is a control against silent and accidental change. It is not proof against the party who holds the repository, and describing it as though it were would be precisely the costume this site exists to avoid.

5.2

The party this does not protect you against is me

Stated plainly, because it is the first objection a careful reader will raise: I compute the digest, I commit it, and I control the repository. Anyone with that access can change a page and its stamp in the same commit, and can rewrite history. What they cannot easily do is make that invisible. A rewritten history breaks every clone anyone else has taken, and a copy you are holding yourself cannot be reached at all.

So if the wording of a published term may matter to you later, do not rely on my copy of it. Print the page, save it, or take your own clone of the repository. The print stylesheet keeps the footer and expands the URLs, which is why printing works as well as it does. That is the ordinary advice about anybody's published terms and I would give it about mine.

6.1

How this index is kept from going stale

An index of documents is the easiest thing on a site to leave behind, and a stale one does more damage to the rest of the page than having no index at all. Two things work against that, and neither is an automatic gate. The repository is the same set of files, so a page that exists but has no row here shows up as a file with no entry, and you can establish that without asking me. The check described at 3.2 covers every page carrying front matter, so running it before publication surfaces a document that has been added or altered without being stamped. Both of those are checks that have to be run, by me before publishing or by you at any time, and neither makes an unstamped or unlisted page impossible to publish. If you find a page on this site with no row here, section 7 is how to say so.

Where a page is withdrawn rather than revised, it comes out of this index and the reason goes into the commit message. The document itself stays in the history. Nothing published here is unpublished quietly.

7

If you find a discrepancy

Tell me. A footer digest that does not match its source, a version number that did not move when a price did, a page in the repository with no row in the index above: any of those is a defect in a control I published, and I would rather hear it from a reader than discover it when it matters. There is a number and a form on contact. Reporting a defect on this page creates no engagement and is not a matter enquiry.

The claim on this page, in one sentence. The published text of this site has not been silently changed, and you can establish that for yourself without asking me. That is all it claims. It is not a timestamping authority, it is not notarisation, and it establishes nothing about any examination or any opinion of mine. Those are tested by reading the method, the limits and the specimen report, and by putting questions to me. Integrity of published text only. No representation as to work product.
